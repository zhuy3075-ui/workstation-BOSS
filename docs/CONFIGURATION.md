# BOSS 工作台：个人资料、公司设置、AI 与备份

[返回软件介绍与完整使用指南](../README.md) · [下载与第一次使用](GETTING_STARTED.md)

自己的真实资料通过界面填写，保存在当前浏览器中，不需要修改或提交源代码。初次使用可选「直接用我的公司」；已经载入示例公司时，可在办公室点击「开始录入我的公司」。后者会清空示例业务数据，已有需要保留的内容时请先备份。

## 把工作台改成自己的

左侧菜单底部打开「**设置**」。设置页修改后自动保存。

| 想修改什么 | 入口 | 可填写的内容 |
|---|---|---|
| 自己的称呼与职位 | 设置 → 老板形象 | 称呼、职位，选择内置男老板 / 女老板形象 |
| 公司 / 门店资料 | 设置 → 公司信息 | 公司 / 店铺全称、简称、类型、行业、城市、口号 / 理念、办公地点 |
| 部门组织 | 设置 → 部门 · 产品 · 渠道 → 管理部门 | 部门名称、颜色、负责人、顺序 |
| 产品与获客渠道 | 设置 → 部门 · 产品 · 渠道 | 添加或删除产品 / 服务、获客渠道 |
| 表扬与提醒规则 | 设置 → 部门 · 产品 · 渠道 → 激励项目 | 项目名称及分值 |
| 员工真实资料 | 团队 → 添加员工，或编辑已有员工 | 姓名、性别、工号、部门、职位、入职日期、生日、手机、技能、目标、画像和备注 |
| 客户资料 | 客户商机 → 新增客户，或编辑已有客户 | 客户名称、联系人、联系方式、负责人、阶段与跟进等 |

「老板形象」使用软件内置角色，不是上传真人照片。公司简称用于侧边栏和前台品牌墙；员工画像与备注可能被相关 AI 功能作为分工参考。

员工较多时，在「团队」使用批量导入：从 Excel 复制包含表头的表格，第一行保留「姓名」「部门」「职位」等字段名。可以先下载界面里的花名册模板，导入后核对部门与人员。

公司资料、员工名单、客户与经营记录都可以日后继续修改。只改公司名不会清除示例员工或合同；想从干净的业务数据起步，应使用「开始录入我的公司」。

## 配置 AI 接口

基础管理、报表和规则预警不依赖 AI。需要直接在软件中拆解目标、提炼商机、生成经营分析或对话时，再配置接口。

1. 在所用服务商控制台创建 API Key，确认该账户可用的模型名称、Base URL、权限和计费方式。
2. 打开「**设置 → AI 接口**」，选择服务商，填写「**API Key**」「**接口地址（Base URL）**」「**模型名称**」。预填值只是起点，以实际服务配置为准。
3. 按需调整「创造性（temperature）」和「发送前隐去员工和客户姓名」。
4. 点击「**测试连接**」。成功后再试一个小任务，检查输出是否符合预期。

代码内置 DeepSeek、通义千问、Kimi、智谱 GLM、豆包、硅基流动、OpenAI、Claude、Ollama 和自定义 OpenAI 兼容接口共 10 类适配，详见 [README 适配表](../README.md#配置-ai)。适配存在不等于服务和预设模型当前一定可用，也不代表免费；价格、模型与账户能力以服务商实际情况为准。

Ollama 需要另行运行本地模型服务并配置允许网页访问的来源；它不是仓库自带的模型。使用自己已运行的本地服务时，填写对应的本地 Base URL 和已安装模型名称。

### 市场雷达的联网搜索

在同一页面的「**联网搜索（市场雷达用）**」中设置「联网方式」，必要时填写「搜索用的模型（选填）」，然后点「**测试联网搜索**」。

搜索模型仍沿用上方同一套**服务商、Base URL 和 API Key**，这里只能改变模型名。例如，不能保留 DeepSeek 的地址和 Key，只填另一家服务商的搜索模型名就让其联网。需要选择匹配的服务商 / 兼容端点、模型和联网方式。

本版本只在你触发搜索时请求，不提供定时监测。联网未配置或不可用时，可以使用「手动搜索链接」查看网页，再「粘贴热点」。原文链接和 AI 结论需要自行核对。

### 连接失败与可选本地中转

| 现象 | 优先检查 |
|---|---|
| Key 无效或没有权限 | Key 是否正确、账户是否有该模型权限 |
| 接口或模型不存在 | Base URL 的完整路径、模型名称 |
| 额度 / 频率相关错误 | 账户余额、额度与调用频率 |
| 浏览器提示跨域或请求失败 | 网络是否可达、服务商是否允许网页直连 |

若确认为浏览器跨域限制，可使用仓库附带的中转。电脑需安装 **Node.js 18 或更新版本**；仅为这个可选中转需要 Node.js，基础应用不需要。

在仓库目录运行：

```bash
node ai-proxy.js
```

保持终端打开，把「接口地址（Base URL）」改成 `http://127.0.0.1:8787/` 加**原来的完整 Base URL**。例如原地址为占位示例 `https://api.example.com/v1`，则填写：

```text
http://127.0.0.1:8787/https://api.example.com/v1
```

请替换为自己的实际接口，原地址中的 `/v1`、`/api/…` 等路径应完整保留。中转默认只监听本机 `127.0.0.1:8787`，转发请求和认证信息到填写的目标地址，代码不保存请求内容。它不会提供模型权限或绕过账户限制。用完在终端按 `Ctrl + C` 停止。

## 数据会保存在哪里、发送到哪里

- **本地存储：** 业务记录、设置、AI 对话和 API Key 保存在当前浏览器的 `localStorage`，没有内置云同步。不同浏览器、设备或打开路径可能对应不同的存储空间。
- **AI 请求：** 使用 AI 功能时，问题以及该功能选用的公司、员工、客户、目标、任务或经营资料会发送到配置的接口；Key 会作为认证信息发送。若用了中转，请求也会经过中转。
- **复制提示词：** 粘贴到网页版 AI 同样会把提示词内容交给该服务，发送前请检查其中的资料。
- **名称替换：** 「发送前隐去员工和客户姓名」根据已有档案替换员工名、客户名和符合条件的联系人名。它不对所有文字做匿名化，不会通用识别手机号、地址、老板称呼、公司信息或备注中的其他敏感内容。

因此，姓名替换不能视为“所有信息均已脱敏”或“手机号绝不会发送”的保证。只带入当前任务需要的资料，并在发送前检查自由输入的文本。

## 备份与恢复

在「**设置 → 数据与备份**」中：

1. 点击「**导出备份**」，保存生成的 `BOSS工作台备份-公司简称-日期-时间.json`。
2. 将备份放在自己掌控的私密位置。它是**未加密的完整状态 JSON**，包含公司资料、员工 / 客户信息、业务记录、AI 对话和已填写的 API Key。
3. 换电脑或浏览器时，先打开软件，再点击「**从备份恢复**」选择 JSON；核对提示中的数量后确认。恢复会覆盖当前全部数据。

**不要把业务备份、真实资料或 Key 提交到 GitHub，也不要把完整备份贴到公开 Issue。** 本仓库的 `.gitignore` 会忽略默认命名的备份及常见私密目录，但改名、强制添加等操作仍可能将它们提交。

清理浏览器、移动 HTML 文件、改变打开方式或更新软件前，先导出备份。尽量使用固定文件位置、同一个浏览器和正常浏览模式；无痕 / 隐私会话结束后，本地数据通常会被清除。

### “重新开始”会保留什么

| 操作 | 影响与保留内容 |
|---|---|
| 开始录入我的公司 | 重建业务数据与部门模板；保留老板形象、AI 设置 |
| 载入示例公司 | 用示例公司覆盖业务数据；保留老板形象、AI 设置 |
| 清空全部数据 | 删除员工、客户、合同、目标、任务等业务内容；仍保留老板形象、AI 设置、公司全称和简称 |
| 从备份恢复 | 用备份状态覆盖当前数据，包括备份中的 AI 设置 |

上述前三项保留的 AI 设置包含 Key。「清空全部数据」不是清除凭据；若不再使用某个 Key，应在「设置 → AI 接口」清空它，必要时到服务商控制台撤销。旧备份中的 Key 不会因此自动消失。
